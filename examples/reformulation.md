# Denied, then recovered

Airlock's refusals are addressed to a machine: a stable reason code, the subject, and a
hint saying what to do instead. This file is the loop that makes that worth something -
each refusal below, and the query its hint implies, both run against the live stack.

The follow-up queries were written by reading the hints, not generated by a model. For the
version an actual LLM drives, run `python demo/agent_reformulation.py --capture`.

## Aggregating a denied column

**The agent asks:** `SELECT COUNT(ssn) FROM dim_users`

**Airlock refuses** with `denied`:

- `AIRLOCK-121` on `column:dim_users.ssn`
- why: Aggregating over dim_users.ssn (classified Classification.SSN) is denied.
- **what to do instead: Use COUNT(*) or aggregate over a non-sensitive key.**

**Reading that hint, the agent sends:** `SELECT COUNT(*) FROM dim_users`

**Airlock answers** `executed` with 1 row(s).

## Filtering on a masked column

**The agent asks:** `SELECT name FROM dim_users WHERE email = 'ada@corp.com'`

**Airlock refuses** with `denied`:

- `AIRLOCK-130` on `column:dim_users.email`
- why: dim_users.email is masked; filtering on it would leak row membership.
- **what to do instead: Remove the predicate, or set predicate_policy: transform to compare masked values.**

**Reading that hint, the agent sends:** `SELECT name, email FROM dim_users`

**Airlock answers** `executed_with_modifications` with 4 row(s).

## Natural language instead of SQL

**The agent asks:** `show me the biggest spenders this quarter`

**Airlock refuses** with `error`:

- `AIRLOCK-406` on `statement:query`
- why: This looks like natural language, not SQL.
- **what to do instead: warehouse_run_query takes a SQL statement, not a question. Call warehouse_list_tables to see what you can query, then send SELECT <columns> FROM <table>.**

**Reading that hint, the agent sends:** `SELECT user_id, SUM(total) AS spend FROM orders GROUP BY user_id ORDER BY spend DESC`

**Airlock answers** `executed` with 4 row(s).
