# examples

Captured request/response envelopes and before/after SQL, regenerated by `python tools/gen_examples.py` (`make examples`) against the live demo stack. Each envelope comes from the real gateway over a policy snapshot compiled from a live DataHub and a real DuckDB warehouse - the same path the demo runs. Do not hand-edit.

- `01_clean_aggregate.json` - SELECT status, COUNT(*) AS n, ROUND(SUM(total), 2) AS revenue FROM orders GROUP BY status ORDER BY revenue DESC
- `02_pii_masked.json` - SELECT name, email, phone FROM dim_users LIMIT 5
- `03_deprecated_substituted.json` - SELECT u.name, u.email, u.ssn, o.total FROM users_raw u JOIN orders o ON o.user_id = u.id ORDER BY o.total DESC LIMIT 10
- `04_predicate_denied.json` - SELECT name FROM dim_users WHERE email = 'ada@corp.com'
- `05_cross_domain_denied.json` - SELECT name, salary FROM payroll
- `06_natural_language_rejected.json` - show me the biggest spenders this quarter
- `07_complex_cte_window.json` - WITH ranked AS (SELECT name, email, ROW_NUMBER() OVER (ORDER BY signup_date DESC) AS rn FROM dim_users) SELECT name, email FROM ranked WHERE rn <= 3
- `08_lineage_inherited_mask.json` - SELECT user_id, contact, signup_month FROM user_report

`before_after.sql` pairs each original query with the SQL Airlock actually executed. `audit.jsonl` is the decision log from this run.

`reformulation.md` shows three refusals next to the query each one's hint implies, both run live. That deny-then-recover loop is the point of addressing a refusal to a machine rather than a person, so it is the file to read first.

`agent_session.md` is a captured MCP session: an agent asks for a customer by SSN, is refused with a reason it can act on, reads the policy off `warehouse_describe_table`, and reformulates into a query that answers the underlying request. Every envelope in it is real; the agent turns were taken by a model reading each response.

`agent_reformulation.md` is generated on demand rather than committed: `python demo/agent_reformulation.py --capture` drives a real LLM through these same tools over MCP, and what it contains depends entirely on the model you point at it. It runs on Anthropic or any OpenAI-compatible endpoint (OpenAI, Together, Groq, a local Ollama or vLLM), so it is not tied to one vendor - but a model that cannot follow a multi-step tool workflow produces a transcript of it guessing column names, which is a real run and poor evidence. `reformulation.md` above covers the same loop without that dependency.
